# 蝌蚪养成记 3D

微信小游戏 WebGL 游戏：使用 Three.js 渲染 3D 池塘、蝌蚪养成、角色青蛙、跳荷叶和荷花池捕虫。
原小程序页面保留为共享玩法源码和浏览器对照预览，不参与小游戏上传。

## 技术方案

- 3D 渲染：`threejs-miniprogram`（内置 **Three.js r108**）
- 画布：小程序 `type="webgl"` Canvas
- 模型：参考皇家玩偶造型的大头短身 3D 青蛙，连贯雕塑头部、凹陷眼窝与笑嘴、绿色虹膜、腮红、宝石皇冠、绒边披风及权杖；蝌蚪保留自然流线形体。不是平面立绘或扫描模型。
- 物理：`cannon@0.6.2`（MIT），用于弹弓抛射、积木碰撞和堡垒坍塌。
- 贴图：皮肤与凹凸贴图在本地生成，不依赖远程资源。

### r108 的两个坑（改代码前必读）

1. **`SphereGeometry` 等还是旧的 `Geometry` 类**，只有 `vertices/faces`，没有 `attributes`。
   必须显式用 `*BufferGeometry`。`art.js` 顶部的 `Geo` 表统一做了探测，
   写成 `new Geo.Sphere(...)`，将来升级到 r125+ 也不会炸。
2. **没有 `CapsuleGeometry`、没有 `BufferGeometryUtils`、`vertexColors` 还是布尔值**。
   合批是自己实现的 `mergeParts`，不要去找 `mergeBufferGeometries`。

## 运行

```bash

npm run build:minigame # 更新小游戏发布包；修改玩法、界面、音效或模型后都需重新运行
npm run build:models # 仅修改头部雕塑生成器后需要；生成资产已包含在项目中
npm run build:audio  # 仅修改音效生成器后需要；生成音效已包含在项目中
```

上传后在公众平台版本管理设置体验版、提交审核，完成平台要求的类目、备案及资质流程后发布。本次配置并未代替账号权限检查、真机测试或平台审核。

## 性能保护

- `mergeParts` 保留原有索引，直接预分配缓冲，不再把每个三角面展开成三个独立顶点。
  国王模型仍为 161,738 个三角面，几何缓冲由约 12.28 MiB 降至 5.37 MiB；
  这不是小程序包体或显存总占用，贴图等资源需另计。
- 每个美术工厂只缓存最近两个服饰模板。重复进入关卡复用几何与材质，动作节点和嘴部锚点独立。
  逐出模板时保留在场实例的资源，最后一个引用释放后回收；页面卸载时清理缓存与场景。
- 叶心计算用椭圆距离的解析极值定位候选，最多做两次落点判定，保留原先的 1% 蓄力格点，
  不改变风、漂移、射程、落水判定、蓄力速度或关卡内容。
- 默认分辨率仍为设备像素比（最高 2）。启动/恢复后等待 2 秒，再观察至少 4 秒和 120 帧；
  持续慢帧时每次降低 0.25，最低不低于原生像素比与 1.5 中较小的值。
  每次调整至少相隔 15 秒，持续流畅后才逐级恢复，避免反复跳变。
  蓄力、跳跃、瞄准、伸舌、弹射飞行和转场期间不调整；只改变 WebGL 像素密度，
  逻辑画布尺寸、相机比例、原生文字和触控坐标不变，没有新增限帧。

上述回归可在 Node 和浏览器中验证，但帧率、发热和功耗仍需用目标真机测试。

## 首页与体验

- 总首页提供游戏开始、角色状态、设置。无伙伴时开始领养；有伙伴时继续原有陪伴。
  档案显示真实存档的成长、三项状态、莲子、冒险次数和本领，不会重置或覆盖伙伴。
- 设置独立保存在 `tadpole-settings-v1`：音效、震动与自动/高清/流畅画质。
  静音会立即停止播放，后台和退出会停止/销毁音频。旧伙伴存档格式不变。
- 首帧先绘制池塘，再分帧准备角色和反射。头部使用 DEFLATE 压缩，服饰的重型曲线、基础网格
  与摆放配方由离线脚本生成，运行时按需解码并沿用有界缓存；fflate 只打包 inflate 解码器并保留 MIT 许可。
- 七种本地音效对应选择、蓄力、起跳、落叶、完美、伸舌和吞咽。落叶会压动叶面并激起水波，
  舌尖收回时有弹性，吞咽时口腔和身体轻微起伏。关卡仍为连续 20 跳，不插入休息弹窗。
- 将军、总裁、公主、高僧、侠客、学生、程序员等使用不同服饰轮廓和道具，肖像待机动作随角色改变。
- 水底、水草保持合批；水面带深浅变化、细波与少量焦散光纹，蝌蚪游动和落叶会产生涟漪。
  水面时间采用相对时钟，避免把 Unix 时间传入 float 着色器后丢失小波动。

## 设计要点

**路线被动。** 19 条路线分成 5 种被动，选路线终于会改变手感而不是只换帽子：

| 被动 | 效果 | 路线 |
|---|---|---|
| 稳重 | 落点判定宽 15% | 国王、女王、霸道总裁、霸道女总裁、佛系高僧、佛系圣女 |
| 轻盈 | 落水机会 +1 | 王子、公主、帅气男大、甜妹校花 |
| 远跳 | 跳跃距离 +10% | 铁血将军、飒爽女将、江湖侠客、江湖女侠 |
| 从容 | 蓄力条走慢 25% | 闲散王爷、IT理工男、天才程序媛 |
| 亲和 | 成长速度 +12% | 荷塘女帝、荷塘画师 |

都是"放宽某个维度"，没有强弱只有风格。实现上就是 `PERKS` 表 + `perkValue(key)` 倍率，
分别接到 `leafScore`（判定）、`setupJumpLevel`（机会数）、`landingFor`（跳距）、
`updateCharge`（蓄力时长）、`applyCare`（成长）五处。

**取景。** 竖屏的水平视场只有垂直的 0.46 倍，按高度取景必然把角色缩成一点点。
养成/选路线/结局按「包住包围盒的球」同时满足两个方向来定机位距离；
跳跃关单独处理：俯角抬到约 60°，青蛙沉到画面下三分之一、荷叶浮到上半屏，
机位再相对跳跃方向左右交替偏 11°，构图不会每跳都一样。
实测青蛙占屏宽 46%、荷叶 60%、遮挡约 1%（改造前青蛙 81% 且正对着荷叶）。

**荷叶小径。** 旧实现用黄金角螺旋撒点，相邻两跳的方向能差 137°，镜头只好每跳重新对正后方——
玩家看到的就是"永远正前方、整个池塘却在乱转"。现在每跳转向有上限（20 跳里实测最大 38°），
靠近池边时沿切线绕，路径是一条真正的"路"。

**参考图角色与材质。** 青蛙改为大头短身的立体玩偶比例。头部通过 SDF 与 Marching Cubes
离线雕塑，脸颊、眼眶、下颌连为一体，眼窝、鼻孔和张开的笑嘴为真实凹面。
绿色虹膜使用弯曲镜片与三点高光，粉红舌头位于嘴腔内，腮红和斑点烘焙到顶点色。
国王使用金色红宝石皇冠、红披风、奶油色绒边、皇冠腰扣与权杖，其他路线沿用独立服饰。
皮肤与绒布有本地凹凸贴图，眼睛、金属使用独立柔光环境反射；颜色按 sRGB 解码后统一显示。
头部使用 16 位索引、量化与 DEFLATE 数据，约 341 KiB；运行时不加载建模库或远程模型。
蝌蚪仍有流线身体、透明尾鳍和阶段性四肢，静态服饰合批以控制移动端绘制开销。
跳跃、捕虫、载具与胜负机位已按新角色比例适配，失败时直立角色会真正向前趴倒。

**养成是一场平衡。** 三个按钮各自只把一项拉满，另外两项同时下滑；成长速度取三项里的**最低值**，
所以"只喂食"会明显变慢，另外两项也会见底（UI 会把最缺的那项标红，见底时直接提示"成长会变慢"）。
养完按最常用的照顾方式给称号（溺爱式 / 温柔式 / 放养式），让那十几次点击有个结果。

**连续 20 跳。** 不出现休息弹窗，也不需要点击继续。每五跳自动记录一次进度。
第一关 3 次落水机会（轻盈路线 4 次）：失手后回到最近检查点，
机会用完后也能从该检查点重试。重跑会恢复检查点的完美数，不能重复刷分。正中叶心（判定距离 < 0.3）额外记"完美"，
给"稳过"之外的第二个目标。

**捕虫有射程。** 舌头只能伸 2.9；虫子在身前前后摆动，有一半时间在射程外。
准星金色=够得着、灰色=太远；舔空会惊飞附近的虫子（往上窜 + 加速，0.78 秒）。
于是第二关从"连着点六下"变成"等它飞近再出手"。

**路线收集。** 通关时把路线记进 `wx.setStorageSync`（存不进去也不影响本局），
首页显示"已相遇 N / 19"，相遇过的路线卡片标 ✓，第一次通关的结局页标"新相遇"。
19 条路线 × 5 种被动，重开才有意义。

**动画。** 起跳是「预备下蹲 90ms → 空中 340ms → 落地挤压 150ms → 回弹 180ms」，
不是一条匀速位移；蓄力时青蛙同步下蹲发抖，落地有挤压拉伸和旋转跟随。

**手感。** 空中点击会进输入缓冲（260ms 内落地就自动接上蓄力），
蓄力时在水面画出真实落点环（绿/黄/红三档），判定和预览共用同一个 `leafScore`。

**关卡。** 20 跳，分为浅水初遇、水草摇曳、荷花深处、池心盛夏四段，间距 2.90~3.85。
第 5、10、15 片自动记录进度并恢复本领，跳跃过程不暂停。水色和荷花装饰随区域变化。后面逐步加入三种机关：

- **漂移叶**：叶心会横向缓慢移动，落点预览会把漂移一起算进去
- **沉叶**（第 11、12、14、18 跳）：落上去开始 2 秒倒计时，叶子肉眼可见往下沉，没跳走就掉下去
- **阵风**（第 16、17、19 跳）：落点被侧风吹着摆，预览环摆到哪就落在哪

第二关捕获 10 只虫：小飞虫缓慢巡游、蜻蜓快速飞行后悬停、蝴蝶上下摆动。
虫子只在青蛙正前方的纵向走廊里出没，准星会显示当前目标和是否进入射程。

**长期陪伴。** 确认路线时取名，名字可在养成页面修改。本地存档保存路线、成长、三项状态、
照顾习惯、莲子和冒险次数。离线不扣状态，不会死亡。首页可以继续陪伴，回池塘仍是同一只伙伴。
目前只有一个伙伴存档位，确认新伙伴的名字后才替换旧伙伴，路线收集独立保留。
冒险单独存档：荷叶从最近的第 0、5、10、15 跳安全点恢复，捕虫保留已吃数量，返程保留方式、进度和战果。
右上角可主动暂停、继续、保存回首页或重开；切后台与主动暂停都不消耗计时，也不会插入跳跃休息环节。

**冒险收获。** 每次通关基础带回 3 颗莲子，下次喂食优先使用，额外补充饱食。
完美跳跃、连续捕虫按本次最高连击每 3 次奖励 1 颗，各最多 3 颗；失手只断连击，不增加惩罚。
划船接莲子或飞机穿环额外最多 3 颗，换方式和重试不会重复刷取。基础奖励与目标仍为 20 跳、10 只虫。
第 1、3、5 次通关分别获得初夏荷花、萤火小灯、荷塘草帽，在家中显示。
同一次结算重复进入不会重复领奖。
奖励和本次冒险标识写入同一份伙伴存档，成功后才清除冒险快照，防止中断后重复领取。

**成长纪念册。** 首页可查看初遇、长出后腿、四肢齐全、长成青蛙、第一次完美落叶、第一次捕虫和历次归来的来信。
照片直接从 3D 场景截取并保存在小程序私有目录，不上传；最多保留最近 48 条。截取失败时仍保留文字回忆。

**互动照顾。** 抚摸按钮和在角色身上滑动均可触发亲昵动作；追泡泡是 10 秒的小互动，
点破 5 个即可提前完成，结束后结算陪玩成长。照顾次数决定伙伴的小习惯。

**结算。** 每局给一个评级（S/A/B/C，只看完美数和落水次数，玩家能自己算出来）+ 用时 + 完美数，
最好成绩存本地（更差的成绩不会覆盖）。同时给出**这条路线的一封"来信"**——19 条路线各一封，
最后再叠一句按养育方式收尾的话（溺爱 / 温柔 / 放养）。分享用 `onShareAppMessage`，
文案带上路线和称号。

## 玩法

1. 直接进入成长路线列表，不再区分男生或女生蝌蚪。
2. 在同一列表选择全部 19 种角色：国王、王子、闲散王爷、铁血将军、霸道总裁、帅气男大、IT理工男、江湖侠客、佛系高僧、女王、公主、荷塘女帝、飒爽女将、霸道女总裁、甜妹校花、天才程序媛、江湖女侠、佛系圣女、荷塘画师。
   每条路线带一个被动（稳重 / 轻盈 / 远跳 / 从容 / 亲和），卡片上直接标出来。
3. 喂食、抚摸、陪玩推进成长。每次只抬一项、另外两项下滑，成长速度由最低的一项决定——
   想快就得轮流照顾。长后腿 → 长前腿 → 变成对应路线的 3D 青蛙，同时拿到一个养育称号。
4. 第一关跳荷叶：长按蓄力、松手起跳，跳过 20 片荷叶。3 次落水机会，失手回到最近检查点；
   正中叶心记"完美"；后半程有漂移叶、会沉的叶和会把落点吹歪的阵风。
5. 第二关荷花池捕虫：底部常驻文字引导，按住昆虫并拖动瞄准，金色准星时松手伸舌，灰色准星则等昆虫飞近；吃到 10 只通关。引导不弹窗、不暂停游戏，也不被捕虫反馈覆盖。
6. 捕虫完成后选择返程：划船、坐飞机，或者用弹弓突袭害虫堡垒。
7. 结局：评级 + 用时 + 完美数 + 路线来信，领取莲子和纪念物后一起回家。转发带上伙伴名字、路线和称号。

## 三种返程

- 划船：角色坐在小舟里，双桨划动；点击划桨可加快返程。左右转向接莲子，碰到芦苇只会轻晃，不扣生命。
- 飞机：角色坐在驾驶舱，螺旋桨转动，沿三维航线起飞并抵达家；左右转向穿过金环。转向支持按钮或水平拖动。
- 弹弓：拖拽蓄力、横向调整偏角，松手发射；也可使用弹射按钮。
  抛物线预览与 Cannon.js 的重力、初速度一致。堡垒的木梁和石块都是真实刚体。
  命中后等待坍塌，再出现四脚朝天、逐渐放大的青蛙；打偏则由大蝗虫挥动棒槌，
  青蛙趴地、头顶转星，场景经过横向与纵向两次高斯虚化。
  两种结果都能重试、改换返程，或保留已经获得的捕虫成果回家。
  发射前可切换木石门楼、双层风塔、护城矮堡三种真实刚体布局。

返程玩法均可跳过：选交通方式时或航行中直接快速回家，也可从暂停菜单保存退出。
返程时间不计入闯关用时。切后台暂停所有返程计时；返程重试和换交通方式不会重复发放莲子。
`postinstall` 会把 Cannon.js 独立构建复制到 `miniprogram_npm/cannon`，同时保留其 MIT 许可证。
小程序新增依赖后建议在微信开发者工具重新构建 npm，再编译；浏览器预览可用 `PORT` 指定新端口。
